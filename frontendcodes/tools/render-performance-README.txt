승혁 — 재생 성능 및 브라우저 검증 절차
작성: 2026-10-18

이번 변경
재생 성능 점검의 JSON 보고서를 schemaVersion:2로 확장했습니다.
단일 동작, 원본/복원 두 칸, 네 칸 비교에서 같은 점검을 사용할 수 있습니다.
브라우저 rAF 콜백과 실제 좌표 그리기 요청은 서로 다른 통계로 저장합니다.
CPU 시간과 갱신 간격 p95/최대, 50ms 초과 간격 수, 표본 범위도 기록합니다.
보고서에는 합성 자료 여부, 입력 FPS/프레임 수, 시점/표시 부위,
화면 크기/배율, userAgent, 개발 빌드 여부가 포함됩니다.

지표 읽기
갱신/초: 그리기 요청에서 프레임 번호가 바뀐 횟수/측정 시간.
rAF 콜백/초: 브라우저가 이 점검에 호출한 requestAnimationFrame 횟수/측정 시간.
둘 다 실제 모니터 표시 FPS나 GPU 작업 완료를 측정하지 않습니다.
CPU: 좌표 갱신부터 WebGL 그리기 요청 반환까지의 시간.
p95 간격: 관측 간격의 95백분위수. 평균에 잘 드러나지 않는 지연 확인에 사용합니다.
50ms 초과: 30Hz 기준 간격(약33.3ms)의 1.5배를 넘은 구간 수.
표본 수집됨: 두 개 이상 동작 갱신을 관측하고, 첫/마지막 갱신 간격이 측정 시간의80% 이상.
이 표시는 통과 판정이 아닙니다. 일부 구간/부족은 동작 길이·정지·WebGL 상태를 확인합니다.
비교 영상이 먼저 끝나 마지막 자세를 유지하면 갱신 횟수가 낮아지는 것이 정상일 수 있습니다.

VSCode에서 직접 확인하기
1. frontendcodes에서 Expo 개발 서버를 실행합니다.
   ./node_modules/.bin/expo start --web --localhost --port 8083
2. http://localhost:8083/sign-player 를 엽니다.
3. 재생 성능 점검을 펼치고 '10초 점검 시작'을 누릅니다.
4. 탭을 열어 두고 창 크기·화면 배율을 유지합니다.
5. 결과를 읽고 '점검 결과 저장'을 눌러 JSON을 저장합니다.
6. /sign-reconstruct 와 /sign-compare 에서 같은 순서를 반복합니다.
7. 탭을 숨기거나 창 크기를 바꾸면 취소 안내가 나오는지도 별도로 확인합니다.
   이 시험은 완료된 측정으로 기록하지 않고 재시작합니다.
8. 실제 성능 판정에는 배포 빌드에서도 같은 조건으로 반복해야 합니다.
   npm run build:web 는 배포 파일을 생성합니다. 기존 배포 방식의 /Sign-Language 경로를 사용하세요.
   배포 버전의 로그인 절차는 그대로 유지합니다.

재현 조건을 함께 기록하기
PC/OS, 브라우저 이름과 정확한 버전, 화면 해상도/배율, 전원 상태,
다른 무거운 프로그램 실행 여부, 개발/배포 빌드, 입력 자료 이름과 합성 여부.
같은 입력·시점·몸/손/얼굴 표시·창 크기로 비교합니다.
30fps 요구사항은 별도 실제 화면 관찰/브라우저 성능 추적과 팀 평가 기준으로 확인합니다.
이번 코드가 자동으로 통과/실패 판정을 내리지 않습니다.

브라우저 검증 기록 (현재 모두 미실행)
Chrome 현재 버전 / 직전 버전: 미실행
Edge 현재 버전 / 직전 버전: 미실행
각 버전에서:

- 영상 목록의 정상 순차 전환·없는 영상 건너뛰기·끝·반복
- 영상 오류 중단·재시도·이전/다음·직접 선택
- API 취소·시간 초과·오류 뒤 재시도
- 파일 가져오기와 녹화 저장
버전/수행일/입력/기대결과/실제결과/증거 경로를 적고, 미실행과 통과를 구분합니다.
과거 합성 데이터로 확인한 일부 Chrome 동작을 이 전체 표의 통과로 대체하지 않습니다.
