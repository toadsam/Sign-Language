현재 PC 위치: /Users/yuseunghyeok/Downloads/Sign-Language-main
② 상단 메뉴 터미널 → 새 터미널을 누릅니다.
③ 아래 명령을 한 줄씩 입력하고 Enter를 누릅니다.

cd /Users/yuseunghyeok/Downloads/Sign-Language-main/frontendcodes
./node_modules/.bin/expo start --web --localhost --port 8083

④ 브라우저에서 작업실을 엽니다.
http://localhost:8083/sign-lab
⑤ 종료하려면 서버가 실행 중인 터미널에서 Ctrl+C를 누릅니다.

현재 PC에는 필요한 node_modules가 설치되어 있습니다.
다른 PC나 새 체크아웃에서는 먼저 frontendcodes 폴더에서 npm ci를 실행합니다.
설치에는 Node.js/npm과 네트워크가 필요합니다. 현재 package-lock.json을 함께 사용하세요.
다른 서버가8083을 쓰고 있으면 그 서버를 확인하거나 다른 포트를 선택한 뒤 주소도 바꿉니다.
이 안내의 localhost 서버는 해당 PC에서만 접근하는 개발 서버입니다.

2. 작업실의 7개 화면

/sign-player: 동작 하나 재생, 몸·손·얼굴 좌표 표시, 속도·시점·구간 조절, 녹화.
/sign-compare: 원본/B1/B2/우리 방법4칸 동시 재생. 각 칸의 이름과 JSON 선택 가능.
/sign-reconstruct: 원본/복원2칸 비교, AI팀 HTML 가져오기, 좌표 차이와 보고서 저장.
/sign-codebook: 토큰별4프레임 코드북 검색·목록·상세 재생. 기본 데이터는 모의 자료.
/sign-generate: 문장 입력·로딩·취소·오류·영상 대체 재생의 모의 응답 시험.
/sign-camera: 카메라 또는 로컬 영상의 손21관절 추출과5초 좌표 수집. PC웹 전용.
/sign-hand-review: 수집한 좌표 재생, 미감지/추출 간격 점검, 품질 보고서. PC웹 전용.
각 화면 상단의 '승혁 작업실 메뉴로' 링크로 돌아올 수 있습니다.

작업실의 연결 상태는 구현 범위 안내이며 서버 상태를 실시간 검사한 결과가 아닙니다.
개발 모드에서는 실습 화면을 로그인 없이 점검할 수 있습니다.
배포 모드에서는 기존 로그인/게스트 접근 검사가 유지되므로 인증 연결을 별도로 확인해야 합니다.

3. 동작 JSON을 재생하는 순서

작업실 → 동작 하나 재생 → 동작 JSON 열기 → 파일 선택 → 재생.
기본 합성 샘플만 확인하려면 파일 없이 재생합니다.
속도0.25~2배, 정면/측면/위 시점, 반복 구간, 몸·손·얼굴 좌표 표시를 조절합니다.
좌표 기반 캡슐·관절 표시이며 리깅된 캐릭터의 표정 애니메이션은 구현하지 않았습니다.

필수 동작 형식(components/sign-player/motion.ts):
- fps: 0초과240이하 숫자 / frames: 1~18000 정수
- joints:125 / units:'shoulder'
- data: float32 little-endian [frames,125,3]를 base64로 인코딩
- 관절 순서: 몸0~12, 왼손13~33, 오른손34~54, 얼굴55~124
- 입력 좌표: x오른쪽, y아래, z카메라에서 멀어지는 방향. 어깨너비 정규화 전제.
- tokens: 음수가 아닌 정수 목록 / unknown: 문자열 목록
- segments: {gloss,start,end} 목록. 프레임 번호0부터, start포함/end미포함.
- source:'model' 또는 'baseline' / demo:true이면 합성 시험 표시
좌표는 유한 숫자이고 절댓값100이하여야 합니다. JSON 가져오기 한도40MB.
base64 문자열이나 프레임 수만 임의로 수정하면 좌표 길이 검사에서 거부됩니다.

4. AI팀 원본·복원 결과를 비교하는 순서

작업실 → 원본·복원 비교 → 학습 결과 HTML 선택 → 클립 선택 → 선택한 클립 불러오기.
실제 학습 결과라면 '합성 시험 파일로 표시'를 해제합니다. 시험 파일에는 체크를 유지합니다.
'모두 재생'으로 나란히 확인하고 아래 좌표 차이 패널과 보고서를 사용합니다.
현재 팀 VQ export의 const DATA JSON을 포함한 viewer.html 형식만 지원합니다(40MB이하).
HTML 스크립트를 실행하거나 서버에 업로드하지 않습니다.
개별 original.json/reconstructed.json을 두 칸에 직접 선택하는 방식도 가능합니다.

명령어 변환이 필요한 경우(frontendcodes 폴더에서):
python3 tools/convert-ai-viewer.py --input /경로/viewer.html --list
python3 tools/convert-ai-viewer.py --input /경로/viewer.html --clip 0 --output /경로/새출력폴더
합성 시험 입력은 위 변환 명령에 --demo를 추가합니다.
자세한 형식과 제한: tools/convert-ai-viewer-README.txt

좌표 차이는 같은 프레임125관절의3차원 유클리드 거리 평균입니다.
어깨너비 기준 거리이며 mm오차나 수어 인식 정확도가 아닙니다.
프레임 수와FPS가 달라지면 수치 계산을 중단합니다. 비교 재생 자체는 가능합니다.
같은 문장/시작 시점/관절 순서/정규화인지 사용자가 확인해야 합니다.
결측 마스크가 없어서 모든 관절을 계산하며 자동 정렬이나 결측 제외는 하지 않습니다.
최대 차이가 동률이면 첫 프레임을 사용하고 이동은30Hz공통 타임라인의 가까운 시각입니다.
'비교 보고서 JSON 저장'은 입력 이름·합성 여부·계산 규칙·부위/프레임별 거리를 저장합니다.
원본 좌표는 보고서에 없으므로 입력 HTML/JSON과 함께 보관하세요.

5. 손 좌표를 수집하고 점검하는 순서

카메라 없이 확인:
작업실 → 손 좌표 수집 → 카메라 없이 화면 점검 → 손21관절 표시.
손 추출 준비를 기다리고5초 좌표 수집 시작 → 수집 결과 바로 점검.
공개 손 사진으로 만든 시험 영상이며 실제 수어 동작이 아닙니다.

내 영상 사용:
내 영상 불러오기 → 브라우저 지원 영상 선택 → 손21관절 표시 →5초 좌표 수집 시작.
200MiB이하 영상. MP4/WebM/MOV를 선택할 수 있지만 실제 코덱 지원은 브라우저에 따릅니다.
영상 처음부터5초를 재생하며 반복하지 않습니다. 5초미만 영상은 관절 표시만 가능합니다.

실제 카메라 사용:
카메라 켜기 → 브라우저 권한 확인 → 손21관절 표시 → 준비 후5초 좌표 수집.
HTTPS 또는 localhost가 필요합니다. 이 안내의 검증에는 실제 웹캠 시험이 포함되지 않습니다.
영상/손 추출은 브라우저 안에서 처리하며 서버로 전송하지 않습니다.
탭을 숨기거나 화면을 떠나면 입력/수집을 중단합니다. 좌우 반전은 미리보기만 바꿉니다.
입력 교체 또는 닫기는 이전 수집 결과를 초기화하므로 필요한 결과를 먼저 저장하세요.

수집 완료 후:
'수집 좌표 JSON 저장' 또는 '수집 결과 바로 점검'을 사용합니다.
바로 점검 결과는 브라우저 메모리로 전달되며 새로고침하면 사라집니다.
점검 화면의 '점검 중인 좌표 JSON 저장'으로 원본 좌표도 보관할 수 있습니다.
저장된 파일을 다시 볼 때는 손 좌표 재생·품질 점검에서 JSON을 선택합니다(5MB이하).
좌표 파일과 '품질 보고서 JSON 저장' 결과를 함께 보관하세요.

현재 수집 형식:
signlingo-hand-sequence-v1, [T,2,21,2], Left/Right 슬롯, XY좌표.
손목 원점·손바닥 크기 기준 정규화. 실제 추출 시각을 보존하고 고정FPS로 늘리지 않습니다.
미감지 손은0좌표와마스크0. 원본XY좌표는 rawFrames에 남습니다.
이 형식은 확정ONNX입력 계약이 아닙니다. 정규화 재생은 전체 손 위치 이동을 재현하지 않습니다.
관측 추출 속도는영상FPS가 아니며 미감지 표본 비율은시간 비율/인식 정확도가 아닙니다.
한 손 동작도 있으므로 자동 합격/불합격 기준은 없습니다. 단어 인식 모델은 미연결입니다.

6. 녹화와 평가 영상 준비

단일/비교 화면의 '전체 동작 녹화'는 처음부터1배속으로 녹화합니다.
비교 화면에서는 녹화할 동작 한 칸을 선택합니다. 화면 시점을 미리 맞추세요.
녹화 중에는 탭을 열어두고 완료 후 영상 다운로드를 누릅니다.
녹화 정보에는 조건이 포함될 수 있으므로 평가 참가자 공유 영상과 분리합니다.
captureStream의30fps는 목표값이며 정확한30fps/CFR를 보장하지 않습니다.

80개 실제 영상이 준비된 뒤(frontendcodes 폴더 기준):
python3 ../viewer/seunghyeok/evaluation/prepare_videos.py --input /입력폴더 --output /새출력폴더
Python3, ffmpeg, ffprobe가 필요합니다. 실제80개 자료는 아직 만들지 않았습니다.
입력은 B1/B2/Ours-H/Ours-HF 각 폴더에 sentence-01~sentence-20.mp4 또는 .webm.
번호 영상 ZIP과 조건 대응표를 분리하고 입력을 보존합니다. 기존 출력은 덮어쓰지 않습니다.
자세한 안내: ../viewer/seunghyeok/evaluation/README.txt

7. 코드 검사와 배포 준비

frontendcodes 폴더에서:
./node_modules/.bin/tsc --noEmit --pretty false
./node_modules/.bin/eslint app/sign-*.tsx components/sign-player components/sign-camera components/public-asset.ts --max-warnings 0

웹 빌드:
npm run build:web
기본 출력은 frontendcodes/dist이고 Git제외 대상입니다.
현재 app.json의 배포 baseUrl은 /Sign-Language입니다. 빌드 자산도 그 경로를 사용합니다.
서버의 배포 경로와 이 설정을 맞추세요. 빌드 성공은 실제 배포/인증/모바일 성공을 의미하지 않습니다.

모바일:
재생 화면은 휴대폰이 접근할 수 있는 웹서버 주소가 필요합니다.
EXPO_PUBLIC_SIGN_VIEWER_URL 또는 화면 입력으로 base주소를 지정합니다.
예: https://서버주소/Sign-Language (개별 sign-player 경로를 붙이지 않음)
휴대폰의localhost는PC서버 주소가 아닙니다. 웹로그인 전달과실기기 파일 처리는 미검증입니다.
