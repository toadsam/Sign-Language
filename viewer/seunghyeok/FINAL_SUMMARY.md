## 4. 검증 숫자

**재생 성능 (M1 · 16GB MacBook, 내장 Retina 60Hz, Chrome 157, 배포 빌드, 합성 샘플 120프레임)**
- 10초 점검: 그리기 갱신 30.10회/초, CPU 평균 1.03ms, 50ms 넘은 간격 300번 중 16번
- 슬로모션(240fps) 7.87초: 화면 갱신 **29.98회/초, 빠진 장 0**, 고르지 않게 보인 장 236장 중 11장(16.7ms 6 · 50ms 5)
- IT-03 기준 "30fps 이상"과 비교하면 갱신 수는 맞다. 합격 판정은 ⚠ 팀 기준으로 정한다
- 11/24 고르지 않은 5%의 원인(Math.floor로 프레임 고르기)을 고쳤다. 배포 빌드 10초 점검 두 번: 갱신 30.0 · 30.1회/초, 간격 p95 34.2ms, 50ms 넘는 간격 0 · 0번(11/23은 16번). 단 앱 안 브라우저(Chromium 156) · 창 460×549라 11/23(Chrome 157 · 1440×812)과 조건이 다르다

**응답 시간 (11/24, IT-06, 배포 백엔드 → VM, 워밍)**
- 새 문장 30건(길찾기 · 교통 · 일상, 승혁이 지은 문장)을 하나씩 보냄: 30건 모두 200 · 동작 있음, P50 0.39초 · **P95 0.63초** · 최대 1.07초(348프레임 문장). 목표 P95 3초 이하
- 30문장 중 13개에 못 그린 낱말이 하나 이상 있었다(아는 낱말 범위의 한계). 콜드 스타트는 서버를 껐다 켜야 해서 재지 않았다
- 도구: `frontendcodes/tools/measure-generate-latency.py`

**실제 문장 모델 재생 (11/17, VM)**
- 5문장 모두 HTTP 200, 응답 0.25~0.76초, 프레임 수를 적은 4문장은 124~164프레임
- 빈 문장 → 400, "!!!" → 422, "ㅋㅋㅋ" → 200 · 0프레임 · 미지원 표시
- 자막 구간이 프레임과 맞게 바뀜(지하철/타다/가다)
- ⚠ 이때 서버는 재훈의 "끼워 넣기" 설정(jjh-accuracy)이었다. 일부 낱말은 모델이 만든 동작이 아니라 대표 동작일 수 있다

**따라 하기 채점 (11/17, 승혁 웹캠 기록 20개, 2문장)**
- 9:1 기준 점수: 잘 따라 함 79~95(중앙 89.5), 다른 동작 0~38
- 65점 기준으로 잘못 통과 · 잘못 떨어짐 0%
- "가다"는 문장 가운데에서도 다른 낱말보다 약 30점 낮음. 앞으로 내미는 동작은 카메라 한 대로 깊이를 못 잡는 것이 주원인으로 보임

**평가 자료 (11/23, VM)**
- 지헌 자료 140 records → 서로 다른 단어 열 43개. 이 중 SEN0892_REAL12(라벨 차이)를 빼면 **42개**(2낱말 13 · 3낱말 12 · 4낱말 8 · 5낱말 4 · 6낱말 5)
- 변환 시험은 43개 × 2조건 성공(JSON 86개)

**자동 검사**
- 프런트 check 도구 15개 통과(가짜 서버가 필요한 check-generation-api는 따로 실행), 평가 도구 검사(prepare 7 · export 5 · fps 6항목), tsc 오류 0

- 30fps 측정은 한 기기 · 합성 샘플 · 단일 재생 화면만 쟀다. 모델 응답 재생 · 비교 화면 · 다른 PC는 재지 않았다.

## 6. AI 사용과 내가 판단한 것

- 코드 · 검사 · 문서 초안은 10월~11/4는 Codex, 11/15부터는 Claude Code로 만들었다. 커밋마다 `Co-Authored-By`, 작업마다 `docs/ai-log/seunghyeok.md`에 기록했다.
- 사람이 정한 것:
  - 지도를 작업 기준으로 삼기, main에서 새 브랜치 파기
  - 채점이 짜다고 판단하고 웹캠으로 직접 기록하기
  - 점수 곡선 · 손 모양 완화 대신 9:1 고르기(비교표를 보고)
  - 손가락 안내를 지우지 않고 끄기
  - 슬로모션으로 실제 화면까지 재기
  - 남의 VM 서버는 켜거나 끄지 않기
  - B1 외부 공유 보류
- AI가 낸 안 가운데 고르지 않은 것:
  - 점수 곡선(제곱근): 다른 동작도 45~50점으로 같이 올랐다.
  - 손 모양 100점 기준 완화: 주먹 감점이 검사 경계에 붙었다.
- 검증하다가 바로잡은 것(AI의 첫 결과가 틀렸던 예):
  - 일괄 녹화 첫 시험: 영상 4개 중 3개가 0.03초인데도 "완료"로 묶였다. 그래서 영상 길이 검사를 넣었다.
  - 30fps 첫 분석의 "빠진 장 6": 영상의 프레임 번호를 직접 읽어 보니 빠진 장이 아니어서 세는 방법을 고쳤다.
  - 손 자리 · 모양 기준선을 둘 다 새 값으로 바꾸자 주먹을 쥐어도 손 모양 100점이 나왔다. 그래서 손 자리만 바꿨다.
