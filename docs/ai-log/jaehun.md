## 2026-09-15 · 샘플 데이터 실측  (커밋 없음)
- 목표: AI Hub 수어 영상 샘플(WORD1501~1520, 표현자 REAL01, 5방향)을 열어 실제 형식과 품질을 확인한다.
- AI에게 맡긴 것: 프레임 JSON 구조 파악, 2D와 3D 비교, 방향별 차이, 값 분포 확인.
- 확인한 사실:
  - 3D(x, y, z, 미터, 정면 카메라 좌표계)가 들어 있고 5방향 파일에서 완전히 같다 → 정면(F)만 읽으면 된다.
  - conf 값이 전부 1이라 정보가 없다 → 입력에서 뺀다.
  - pose 25점 중 하체 12점은 10px 간격의 가짜 값 → 상체 13점만 쓴다.
  - 3D가 떨린다(손목–검지 뿌리 길이 6.7~9.7cm) → 스무딩과 뼈 길이 보정이 필요하다.
  - 단어 클립은 손 내린 자세에서 시작하고 끝난다 → 단어를 이으면 손이 떨어진다(문장 데이터가 필요한 이유).
  - 샘플에는 형태소 · 단어 이름 라벨이 없다.
- 남은 것: 정식 데이터에 라벨과 문장(SEN) 데이터가 있는지 확인.

## 2026-09-22 · 2학기 방향과 좌표 표현 결정  (커밋 없음)
- 목표: 친구 계획서(수어링고 v2: 클립 사이 전환만 생성 + 웹캠 채점)와 「손짓의 알파벳」(토큰 생성) 중 하나로 정한다.
- 내가 판단한 것:
  - 「손짓의 알파벳」 토큰 생성 방식으로 간다. 웹캠 채점은 도전 과제, 클립 이어붙이기는 비교 기준선으로 둔다.
  - 논의 자료의 2D 137점 대신 **3D 125점(하체 12점 제외, 375차원)**을 쓴다. 3D가 있으니 아바타에 바로 연결할 수 있다.
  - 손실은 위치 + 속도 + 손가락 상대좌표, 손 가중치, EMA 자모표 + 안 쓰는 코드 재할당으로 간다.

## 2026-09-22 · 데이터 정리 파이프라인과 자모표 첫 구현  (커밋 a15ea14)
- 목표: 샘플 20단어로 데이터 정리 → 자모표 학습 → 복원 확인까지 한 번 끝까지 돌린다.
- AI에게 맡긴 것:
  - `prep/preprocess.py`: JSON → 125점 3D npy (결측 보간, Savitzky–Golay 스무딩, 손 뼈 길이 보정, 목 원점 · 어깨 정렬 · 어깨너비 정규화, 움직임 구간 검출)
  - `vq/model.py`: T2M-GPT 구조 VQ-VAE (1D 합성곱, 시간축 1/4 → 토큰 1개 = 4프레임)
  - `vq/train.py`: 부위별 오차(mm), 코드 사용률, 뷰어 내보내기
  - `vq/render_figures.py`, `viewer/skeleton_viewer.html`: 원본과 복원 비교 그림 · 뷰어
- 처음 계획 → 바꾼 것:
  - 실행 계획의 손실(복원 L1 + 속도 L1)에 **손가락 상대좌표 손실**과 부위 가중치(손 2 : 상체 1 : 얼굴 0.5)를 더했다. 평균 오차만 보면 손가락이 뭉개져도 작게 나오기 때문이다.
  - 샘플이 20단어뿐이라 자모표 크기를 계획의 512 대신 128로 줄여 과적합 테스트를 했다.
- 검증 (샘플, 3,000번 반복, 29분):
  - 학습 단어 복원 오차 8.7mm (손 12.8mm), 코드 81/128개 사용
  - 처음 보는 단어 4개 33.6mm (손 58.8mm). 20단어로 학습했으니 일반화는 판단할 수 없다.
- 남은 것: 정식 데이터, 수행자 단위 분할.
