## 2026-10-24 · 생성 모델 개발 현황 확인과 worktree 병렬 작업 계획

- 목표: 기존 팀 작업을 이해하고 지헌 담당 생성 모델·추론 서버·Spring 연결을 다른 Codex 세션에 나눌 수 있는 계획을 작성한다.
- AI에게 맡긴 것: 역할분담 문서, 코드·계약·E5 인수인계·Git 이력 검토, GCP sign-ml 읽기 조회, 작업 경계·의존성·검증 기준을 Markdown으로 작성. 도구는 Codex(Sol로 현황 확인 후 Astra로 계획 작성)다.
- 처음 계획 → 바꾼 것: 데이터 필터 → E5 검증 → 서비스 → 학습의 순차 흐름에서, 실제 데이터 없이도 A(학습), B(생성), C(서비스)가 가짜 입력으로 병렬 개발하고 정해진 지점에서 통합하는 흐름으로 구체화했다. 단어 생성과 문장 생성을 별도 완료 단계로 나눴다.
- 내가 판단한 것: 지헌은 이 세션을 설계·계획 문서·작업 배분 용도로 사용하고, 다른 세션을 git worktree로 분리해 병렬 구현하기로 했다. 설계 세션의 모델을 Astra로 전환했다. 구체적인 A/B/C 분할과 인터페이스는 AI가 작성한 실행 전 제안이며 실제 실행·팀 계약 승인과 구분한다.
- 검증: 기준 소스 cca2d5721202da0983c74598c0791aba6ab42266에서 생성 학습 코드의 필터·GPU·재개 처리 부재, Generator/serve 부재를 확인했다. GCP 조회에서 sign-ml은 n1-highmem-8, RAM 52GiB, T4 1개, Spot, 정지 상태였고 디스크는 30GB+150GB였다. 실제 데이터·모델 수령, 서버 내부 환경, 학습 성능은 검증하지 않았다. 이번 산출물은 계획 문서이며 모델 테스트 결과가 아니다.
- 남은 것: 계획·내부 인터페이스 검토, 계획을 포함한 공통 기준 커밋과 worktree 준비, A1/B1/C1 착수, E5 실제 수령 확인, 팀의 API 세부 정책 확인, GPU 실행 전 승인. 코드·계약·데이터는 수정하지 않았다.

## 2026-10-24 · 공통 계획 커밋과 A·B·C worktree 준비 (공통 기준 db0d299)

- 목표: 다른 Codex 창에서 작업 범위를 나눠 시작할 수 있는 로컬 Git 작업 공간을 준비한다.
- AI에게 맡긴 것: 계획 문서 6개만 명시적으로 스테이징·커밋, 전용 브랜치·worktree 3개 생성, 브랜치·기준 커밋·작업 트리·지시서 존재 확인.
- 처음 계획 → 바꾼 것: 사용자의 공개 범위 질문에 따라 계획 문서에 로컬 커밋과 GitHub push의 차이, 기능 브랜치 push에도 계획 문서가 포함되는 점을 명시했다. 공통 기준 커밋은 db0d299이며 이 준비 기록은 조정 브랜치에서 별도로 남긴다.
- 내가 판단한 것: 지헌은 제안한 공통 기준 커밋과 worktree 준비를 진행하도록 지시했다. GitHub 공개 여부를 질문했으며, push하거나 문서를 비공개로 전환하라는 요청은 하지 않았다.
- 검증: A는 `feature/gen-training-jiheon` / `C:/Users/USER/Documents/GitHub/Sign-Language-training`, B는 `feature/gen-inference-jiheon` / `C:/Users/USER/Documents/GitHub/Sign-Language-inference`, C는 `feature/gen-service-jiheon` / `C:/Users/USER/Documents/GitHub/Sign-Language-service`. 세 worktree 모두 HEAD=db0d299, 변경사항 없음, 해당 작업 지시서 존재를 확인했다. 기존 backend/bin과 역할분담 원본은 커밋하지 않았다. 원격 push·모델 학습·VM 시작은 수행하지 않았다.
- 남은 것: 지헌이 각 폴더를 별도 Codex 창으로 열어 A1/B1/C1 지시문을 전달한다. 각 창의 실행 결과는 조정 세션에서 검토한다. 실제 E5 수령과 GPU 학습 준비는 후속 작업이다.

## 2026-10-24 · 계획 문서를 로컬 전용으로 전환

- 목표: docs/plans의 계획·지시서·세션 보고서를 로컬에 보존하면서 GitHub에 올라가지 않게 한다.
- AI에게 맡긴 것: Git 제외 규칙, 미공개 계획 커밋을 작업 브랜치 이력에서 제외하는 정리, 로컬 pre-push 검사, worktree별 문서 사본 동기화.
- 처음 계획 → 바꾼 것: 계획을 공통 Git 커밋으로 전달하는 방식을 로컬 파일 사본 전달 방식으로 변경한다. 위 기록의 db0d299 및 후속 49f0254는 과거 로컬 준비 이력이며 앞으로 작업 기준으로 사용하지 않는다. 새로운 공통 기준은 계획 문서를 포함하지 않는다.
- 내가 판단한 것: 지헌이 docs/plans 문서를 앞으로도 로컬 전용으로 유지하고 push 대상에서 제외하도록 지시했다. 각 구현 세션에는 담당 지시서 경로를 전달하여 작업하도록 한다.
- 검증: 구현 변경이 없는 네 작업 브랜치와 기존 사용자 파일 상태를 확인했다. 루트 계획 문서가 미추적·ignore 상태임을 확인하고, 네트워크 연결 없이 pre-push 훅에 과거 계획 커밋/깨끗한 커밋/브랜치 삭제 입력을 주어 차단/허용/허용 결과를 확인했다. 최종 브랜치 이력과 각 로컬 사본은 정리 후 별도로 대조한다.
- 남은 것: 각 세션의 A1/B1/C1 구현. 계획은 로컬에서 동기화하며 상세 내용을 다른 추적 파일에 통째로 옮기지 않는다. 일반 개발 기록과 구현 코드는 기존 정책대로 관리한다.

## 2026-10-28 · 단어 GPT 조건 문제 진단과 3000단어 재학습 (커밋 bbd948a)

- 목표: 어떤 단어가 들어와도 그 단어의 수어 동작을 생성하도록 단어 GPT 성능을 올린다.
- AI에게 맡긴 것: 조건 사용 진단(rank_words), 생성 동작–정답 동작 거리 채점(gen_match), 조건 강화 구조(cond_every, null_cond+guidance), 50단어 빠른 확인과 3000단어 학습 스크립트(quick_fit), 서버 실행과 결과 정리.
- 처음 계획 → 바꾼 것: 승현의 인식 모델로 채점하려 했지만 아직 쓸 수 없어서, 생성 동작을 E5로 복원해 그 단어 train 정답 동작과의 거리 순위로 채점하는 방식으로 바꿨다. 기존 모델 추가학습(warm-start) 대신 새로 학습했다. 50단어 확인에서 기존 구조도 완벽히 배우는 것을 보고, 원인을 구조가 아니라 학습량 부족으로 판단했다.
- 내가 판단한 것: Codex가 만든 HANDOFF 다음 계획은 버리기로 했다. 인식 모델 없이 정답 동작과 직접 비교하는 단순한 채점을 요구했다. 기준선 측정 → 50단어 확인 → 3000단어 A·C 동시 학습 순서와 서버 학습 실행을 승인했다.
- 검증: 기존 best2280은 train에서도 단어 조건 순위 top1 0.25%(토큰 빈도 기준선 val 30%, train 81%), 생성 채점 top1 0.8%. 3000단어 약 30 epoch(T4, 약 75분) 후 200단어 생성 채점(상체+양손 55점) top1/top5: A 45.0%/73.5%, C(guidance 1) 62.8%/87.2%, C(guidance 2) 74.2%/91.7%, 실제 val 동작 상한 71.7%/87.2%. 단어 간 평균 거리 생성 0.576, 실제 0.552로 같은 동작 반복 없음. 새 테스트 8개 통과.
- 남은 것: guidance 2에서 토큰 2개짜리 짧은 생성이 섞임(최소 길이 정책 필요). training.py·Generator·추론 서버에 C 구조 연결, 모델 생성 샘플 JSON을 승혁에게 전달, 육안 비교 뷰어 확인.
